# fishroom：玩家自己的 DSH、QQ 与记忆接入

## 先玩空房子

Android 首次安装不包含角色卡、聊天、日记、正式存档或任何账号配置。外部服务默认关闭；没有 DSH 也可以启动，进入商店、背包、旅行、签到和日记空状态。角色默认显示，旅行中隐藏；DSH 只影响聊天、旅行信和日记，不影响角色本身。聊天生成不可用时显示未接入状态；旅行排期和已购车票继续保留，尚未生成的信保持 pending，不冒充 AI 已生成正文。

APK 只运行游戏。DSH、companion、memory 和可选 QQ 桥接运行在玩家自己的电脑上；电脑关闭时，手机仍能游玩本地部分。安装游戏不会启动 QQ、发送消息或替换人格卡。

## 准备自己的电脑运行环境

1. 按所使用 DSH 发行版的官方说明安装、登录并启动自己的 DSH。确认其本机宿主地址和端口；不要照抄别人的宿主端口。DSH 的账号凭据留在电脑的 DSH 用户目录中。
2. 使用与你的游戏版本配套、已清理个人信息的 companion/memory runtime。它们不在 APK 内，也不能从开发者工作目录中直接整包复制。runtime 需要 Node.js 22 或更高版本及配套 DSH 客户端、preset 校验依赖。
3. 在电脑上配置自己的主人身份、机器人身份和记忆目录；使用同一份 memory 服务供游戏与 QQ 使用。每位玩家使用独立目录和自己的起始 epoch。不要导入开发者的冻结记录、正式记忆、角色卡或 connection.json。
4. 在 runtime 根目录启动 memory 和 companion，保持终端运行：

```powershell
$env:MEMORY_PORT = '8770'
node integrations/memory_service/server.mjs
```

另开终端：

```powershell
$env:COMPANION_PORT = '8765'
$env:MEMORY_URL = 'http://127.0.0.1:8770'
node companion_core/server.mjs
```

以上是服务入口，不是 DSH 安装命令。不同 DSH 发行版的登录和 preset 安装方式不同，请使用其支持的设置或导入流程。当前开发源码的 memory 身份和起始 epoch 与开发环境绑定；公开分发前，发布者必须另行提供可配置的干净 runtime。只有 APK 和本文件时，可以游玩空房子，尚不能直接获得可分发的电脑 runtime。不要运行开发环境的一键服务脚本来替代玩家配置。

本机默认关系：游戏 → companion `8765` → 用户 DSH；companion/QQ → 同一个 memory `8770`。DSH 宿主 URL 由电脑端解析，通常使用电脑本机回环地址。这与手机访问电脑 runtime 的地址是两件事。

## 三个 preset：同一人格，不同工具权限

| 通道 | preset 用途 | 工具边界 |
| --- | --- | --- |
| game | 游戏聊天、旅行信 | 无工具，关闭 runtime context |
| diary | 日记整理和回忆继承 | 无工具，关闭 runtime context |
| QQ | QQ 私聊/群聊适配 | 配套桥接允许的 QQ 发送、表情工具及玩家自己的 ACL |

三个 preset 引用同一份由玩家维护的人格配置；游戏不会从 APK 注入一份开发者人格。QQ 工具留在 QQ 通道，游戏和日记不得获得发送消息或执行命令能力。连接测试会检查三通道人格配置是否一致、game/diary 工具是否关闭及 QQ 所需工具是否存在；手填相同名称不能代替权限检查。

同一个 DSH、同一个 memory、不同 preset，才能让不同入口使用同一人格与适当的记忆。群聊记忆继续按群隔离；私人记忆不能因此公开到群聊。接入文档不包含或授予任何 QQ 发送授权。

## 在游戏里填写地址

1. 设置 → **DSH / companion / memory 设置**，先填 companion 和 memory 地址。保持外部服务关闭也可以继续游戏。
2. 电脑本机运行游戏可用 `http://127.0.0.1:8765` 和 `http://127.0.0.1:8770`。
3. **手机的 `127.0.0.1` 指手机自己，不能访问电脑。** 手机需要电脑 LAN 地址或 Tailscale 地址，例如 `http://192.168.1.20:8765` 或 `https://你的电脑名.你的尾网.ts.net`。示例仅说明地址形式，实际填你自己网关的端口。
4. 保存并启用后，进入 **日记 → DSH 连接设置**，填写电脑 runtime 能访问的 DSH URL，以及自己的 game、QQ、diary preset ID，执行连接测试并保存。此处 DSH URL 可继续是电脑的 `127.0.0.1`，因为请求由电脑 companion 发出。

客户端接受私网 IPv4/Tailscale HTTP 地址和 HTTPS 地址；地址不得带用户名、密码、路径或查询参数。客户端支持配置地址不代表电脑服务已经对手机开放。

当前 companion/memory 默认仅监听电脑回环地址，并检查 Host/Origin。**不能仅把手机设置里的 IP 改成 LAN IP 就连接成功。** 玩家需要自己部署受身份验证和访问控制保护的私网网关：转发到电脑回环服务，适配上游 Host，限制只有自己的设备可访问。建议 Tailscale 私有 HTTPS 网关，禁止公开 Funnel。memory 还包括管理和原始记忆接口，不能直接开放整个端口；只放行游戏日记所需接口，并保护管理操作。不要直接修改服务的默认绑定来暴露个人记忆。

本次 Android 包不附带手机网关或 runtime 安装器；网关部署是独立的可选工作，不影响离线启动。公网无认证转发不可用作上述配置的替代。

## 离线、pending 与日记含义

- 旅行/库存/签到使用本机存档；DSH 断开不扣除已购物品，也不重置进度。
- 未生成旅行信保留 pending。恢复服务后客户端按原旅行和信件索引补投；已有正文、排期和照片 ID 不因内容包更新重写。
- 失败聊天由玩家手动重试。日记服务未启动时显示空状态/服务未连接，不伪造回忆。
- 日记是发生过的事的回忆，不是人格定义。人格卡始终由玩家自己维护；回忆和教学资料不能覆盖人格卡。
- 教学内容只是知识。明确提供知识不表示允许向 QQ 发送消息，不会自动变更主人身份或工具权限。

## 内容更新与备份

从可信来源下载本地 ZIP 后，在设置中选择 **导入本地内容包 ZIP**。游戏先备份当前存档，再检查路径、类型、版本与 SHA256；成功后切换内容，旧商品拥有记录、库存、车票、旅行、信件、相册、签到和余额继续保留。内容包不能携带存档或脚本，不会自动从云下载。

下架商品和未知 ID 保留为归档，不退款、不删除。旧照片缺失时显示占位，不把旧信配到新图。已安装版本不能同名覆盖；失败信息会保留在设置页。

设置中的 **导出存档** 用于进度备份；恢复用 **导入存档**，它会明确提示覆盖当前进度。内容包导入与存档导入是两个按钮。换机还需备份当前和历史引用的 `user://content/` 目录及 runtime 地址设置。只有 save.json 不包含内容包图片，缺少当前内容版本时游戏会阻止覆盖存档，请先恢复对应目录。旧版本的内容目录不能随意删除，历史相册可能仍引用其中图片。

电脑端的 DSH 用户配置、人格卡、memory 原始记录、日记和 companion 队列单独备份，先停止对应写入服务再复制。不要把这些备份上传到公开网盘或随游戏 ZIP 分发。Android 卸载可能删除应用私有数据，覆盖安装通常保留；需要备份时不要先卸载。

## 常见故障

| 现象 | 检查 |
| --- | --- |
| 空房子、未接入 DSH | 外部服务是否启用、电脑 DSH 是否启动、preset 测试是否通过 |
| 手机连接失败，电脑正常 | 手机是否填了回环地址、同一 LAN/尾网是否连通、私网网关与访问控制是否配置 |
| companion 正常、日记为空 | memory 地址、服务状态、当天是否有可整理记录；不是每次打开都生成日记 |
| 人格/工具校验拒绝 | 三个 preset 的人格配置一致；game/diary 无工具；QQ 适配器所需工具齐全 |
| 旅行一直 pending | DSH 连接、生成超时、配套 runtime 是否支持新增地点；本地行程仍保留 |
| 内容包拒绝 | manifest 是否齐全、文件是否改动、版本是否兼容、ZIP 是否含额外文件或链接 |
| 缺少当前内容、不能保存 | 恢复与存档 content_version 对应的原内容目录，不要重置存档 |

反馈问题时只提供脱敏的错误码、游戏/内容版本和设备信息，不附账号 Key、connection.json、完整聊天或记忆正文。
